# 40 · 识别与编码

本篇回答：B 怎么知道 A 缺什么；缺的部分怎么编；三层怎么分、怎么统计。
只用基础信号：行 hash、位移投票、色数与游程、A11y 矩形。不用模型。

思路来自屏幕内容编码（HEVC-SCC / AV1 的 Palette 与块内复制）和远程桌面的 hash 运动估计：屏幕内容边缘锐利、颜色少、重复多。

## 1. 每帧的步骤

1. 对每个区域算行 hash（§2）。
2. `Scroll` 区域求位移，更新采集头的内容坐标（§3）。
3. 每一行和该页行 hash 表比，得到“A 缺的行”（§4）。
4. 缺的行先找引用（`Copy`），找不到的切成矩形（§4、§5）。
5. 矩形分类、选编码器（§6–§8）。
6. 组装成 `Tx`，更新行 hash 表，记统计（§9）。

## 2. 行 hash

- 每个区域每行一个 64 位 hash，函数签名自 M1 起内置**列掩码（有效列区间）**：覆盖区域宽度，但**掩掉（不计入）**右缘滚动条窄带（`sb_w`）以及压在该滚动区之上的 `Fixed` 浮层（如 FAB）所在的列区间（列掩码生成归 `region.rs`）。
- **零拷贝与增量计算**：JNI 侧直接就地读取 `ImageReader` 的 RGBA 平面（零拷贝）；每行先按有效列区间与上一帧同一位置 `memcmp`，只有像素变化的行才用 SIMD 重算 64 位行 hash。
- 每行记录**信息量**（颜色游程数，纯色行为 0）与在上一帧中的出现频次。
- 一段行的 hash = 各行 hash 的折叠。两端用同一个定义（都在 rd 里）；另按固定余数 / winnowing 抽出约 1/32 的**稀疏锚点行**供跨会话页面识别与画布对齐（[20](20-pages.md) §2）。
- 行是最小单位，不依赖块大小，所以高密度屏、密集列表不需要特殊处理。只有图片对齐和块统计用到块（`block_dp`，按屏幕密度换算成像素）。

信息量与稀有度的用途：纯色行和周期性分隔线会产生大量假匹配。位移投票和引用查找**不拿信息量为 0 的行当证据**，且投票权重乘上该行 hash 在上一帧的**稀有度（逆频率）**。

## 3. 位移与对齐

输入：上一帧和当前帧在滚动区内的行 hash。输出：dy，以及当前帧里哪些行段是上一帧平移过来的。只在 `Scroll` 区域内算。

1. **已知预期位移**（刚注入了滚动）：直接验证“当前帧第 y 行 == 上一帧第 y + dy 行”。按信息量加权，匹配的比例够高就采用。
2. **否则投票**：对每个有信息量的行，在上一帧里找 hash 相同的行，给对应的 dy 投票（权重 = 信息量）。同一个 hash 在上一帧出现太多次的不投。取票数最高的 dy，要求明显高于第二名，并且能验证出足够长的连续匹配行段。
3. **多位移**：一个 dy 认下它能匹配的行段后，剩下的行再投一轮，最多 `shift_rounds` 轮。用于折叠标题栏和列表同时移动的情况。
4. 都不成立 → 这一帧没有位移。

**画布对齐**（重进页面、resize 之后、位移丢失之后）用的是同一个投票，只是把“上一帧”换成该页的行 hash 表。对齐成功得到采集头的内容坐标；失败 → 该区域画布清空（`Clear`）。

与 A11y 滚动量交叉校验：由于 Android 的 `TYPE_VIEW_SCROLLED` 事件会被节流到 ~100 ms 并累加 delta，交叉校验**只在页面滚动停稳后做**（对比像素累计位移与 A11y `scrollY` 或 `CollectionItemInfo.rowIndex`）。两者对不上时以像素为准，`map_exact` 置假。

## 4. A 缺什么

采集头位置确定后，当前帧每一行都有了内容坐标 y。

- 行 hash 表在 y 处的值等于当前行 hash → A 已有，跳过。
- 不等或为空 → 缺。
- 被吸顶标题 / FAB 挡住的矩形列区间 → 只跳过被遮挡的列段，同一行的其余列照常写画布；右缘窄带（`sb_w`）按 [30](30-scroll.md) §7 做**多帧一致性**：按已知位移对齐后两帧（或三帧多数）逐像素一致才写画布，否则该行待定。
- 缺行在 A 的视口内 → 现在发。在视口外 → 归预取，按 [10](10-dataflow.md) §6 的规则发；没轮到发的行不记入表。

把连续的缺行合成横带，然后：

1. **找引用。** 用行 hash 在可引用的内容里找连续相同的行段（§5）。够长就发 `Copy`。
2. **纯色行** → `Fill`。
3. **剩下的定左右界。** 如果上一帧同一内容行和 A 一致（原地小变化的常见情况），逐列比较当前帧和上一帧，得到变化的列范围；否则取整行宽。
4. 得到的矩形交给 §6。

原地变化（该位置 A 原本有内容，且不是换页）一律先包成 `Overlay`（[20](20-pages.md) §5）；新露出的内容直接写画布。

## 5. 引用：能 `Copy` 什么

可引用的内容 = A 手里已有的内容：
| 来源 | 阶段 | 例子 |
|---|---|---|
| 本页各画布的行、远跳零散段、刚被替换的临时页 | M2 | 同一列表里重复的分隔条、相同的条目；远跳零散段命中；临时页转正式页搬移；列表高度变化后的复用 |
| 返回栈上其他页的画布 | M5 | 新页和上一页共用的顶栏；返回后局部不同的页面 |
| 精灵池 | M4（图片）/ M5（无损） | §7、§8 |
| 本 `Tx` 内更早写入的内容 | M5 | 首屏里重复的条目 |
规则：

- 下行是一条有序流，所以 B 已经发出去的内容都可以引用，不用等确认。
- 匹配从信息量大于 0 的行起头，最短 `ibc_min_rows` 行。
- `Copy` 可以带 x 偏移，用来表达整块横向平移（整列平移、横向偏移的布局）。
- 跨页引用只允许指向返回栈上的页（A 保证它们在内存里）。
- 源和目标在同一张画布且重叠时，A 按“先读后写”处理。

## 6. 选编码器

| 矩形是什么 | 怎么判断 | 编码 |
|---|---|---|
| 纯色 | 一种颜色 | `Fill` |
| 文字、symbolic 图标、控件 | 条带内颜色数 ≤ 256（允许极少量低频色 escape） | `Lit{Palette}`：按条带切分调色板 + escape + 亮度序 token 流，再过 zstd |
| 渐变、阴影、颜色多但不是照片 | 其余 | `Lit{Residual}`：通道去相关 + 行预测，再过 zstd |
| 照片类图片 | A11y 的图片节点矩形 + 像素确认（颜色多、几乎没有长游程）；没有 A11y 时只看像素 | `Image`（有损，§7）。`img_lossy` 关闭时用 `Lit{Residual}` |
| 小而重复的控件 | A11y 的小图标 / 开关 / 复选框节点 | `SpriteDef` + `Copy`（§8） |

- **条带级 `Lit{Palette}`（避免整屏色数超 256 退化）**：真实 App 整屏色数中位数常在 300–600 色，直接对大矩形建表会突破 8-bit 上限。编码大块文字/控件脏区时先按横条带（如 64 行）切分：每条带局部调色板 ≤ 256 项（1 字节索引），超出的极少量抗锯齿过渡色走 escape 像素；调色板**按亮度排序**，索引平面先走轻量 `RUN`（行内游程）+ `COPY_ABOVE`（复制上一行）token 化，再进 zstd。行预测滤波会让锐利文字变大，绝不对 Palette 索引使用。
- **位置相关微弱阴影**：Material 卡片若带屏幕固定光源的微弱阴影，滚动后同一行阴影灰阶会有 1–2 LSB 漂移。不为此拆第 4 层；若实测某 App 因此频繁失配，仅对该区开启 ±2 LSB 平滑梯度容差（不触发重发）。
- 拿不准 Palette 还是 Residual 时两种都编，取小的。矩形很大时先抽样再决定。
- A11y 的作用是给出**切在哪**：图片节点、图标节点的矩形就是切分线。列表里的图标通常尺寸相同、左边缘对齐，按节点矩形切出来的图标可以直接互相比较。A11y 说的和像素对不上时以像素为准。
- 可选优化：原地变化的 `Lit` 可以把“变化前的同一矩形”作为 zstd 字典（`Lit.dict`）。

## 7. 图片（有损）

- 矩形对齐到 A11y 图片节点的边界；没有 A11y 时对齐到块网格。
- B 用 rd 里的 JPEG 编码器编；A 用浏览器原生解码（`createImageBitmap`），rd.wasm 不带 JPEG 解码。`img_q` 可调。
- **首屏与预取拆小 `Tx`（文字先发）**：同一帧里既有文字又有图片时，B 先发一条只含底色 `Fill`、文字 `Lit` 和图片底色占位的 `Tx`（让首屏在 ~100 ms 内立即出字且可点），再把图片按 **8–16 KB** 粒度拆成多条后续 `Tx` 下发，防止大图片阻塞交互响应。
- A 解出的像素 B 无法预知，所以有损像素永远不参与行 hash 比对和校验（§10）。
- **圆角和不规则边缘**：图片矩形里混着周围的底色。矩形内与底色完全相同的像素用一张 1 位掩码标出，解码后恢复成底色。这样圆角外侧不会有压缩噪点。
- 每张完整的图片按源像素 hash 登记为精灵，再次出现时 `Copy`（应用图标在多个列表里反复出现）。
- **被采集范围截断的图片**：在 A 视口内 → 立即按截断的矩形发，不登记精灵；不在视口内 → 等采到完整再发。
- 行 hash 始终按 B 的源像素算，A 不需要、也无法用 hash 校验有损像素。

## 8. 精灵（无损）

- 候选：A11y 里尺寸小的图标、开关、复选框、返回键这类节点的矩形。
- 第一次见：`SpriteDef{hash, …}`，然后 `Copy` 到位。再见到相同 hash：只发 `Copy`。
- 精灵跨页共享，随缓存持久化。池满按“无页面引用 + 最久未用”淘汰，B 下发 `SpriteDrop`。
- 同一图标在不同底色上是不同精灵（按下高亮时的图标）。这是预期的。
- 没有 A11y 的页面不找精灵，靠 §5 的行引用。

## 9. 三层与统计

每个 Op 写入时带两个标签：

- 层：`bg`（`Fill`、`Lit`、画布之间的 `Copy`）、`lit`（精灵、图片）、`fg`（视频区，M6）。
- 省流机制：没省（字面量）、滚动（A 本地合成）、页面缓存（返回 / 重进）、行引用（`Copy`）、精灵。

B 每秒汇总一次，经 `Stats` 发给 A：各层字节与占比、各机制省下的字节与百分比。

“省下的字节”怎么算：被省掉的面积 × 该页该层最近的每像素字节均值。这是估算，够面板用。bench 里用真实的影子编码（把被省掉的矩形真的按字面量编一遍）给出准确值。

l 面板要能回答：精灵缓存、滚动、长截屏（页面缓存）各省了百分之多少。

## 10. 校验

- 调试档（`verify`）：B 在 `Tx` 末尾附 `Verify{region, y0, y1, fold}`，A 用同一个 hash 定义计算并比对，不一致回 `VerifyFail`。
- 不参与校验的像素：有损图片、模态页下面压暗的背景。rd 的解码器带一张调试用的掩码（每像素一位，`Image` 置位、`Fill` / `Lit` 清零、`Copy` 跟着搬），算 hash 时跳过含这类像素的行。
- bench 对每个场景做同样的校验，并要求图片矩形之外逐像素一致。

## 11. 边界情况

| 情况 | 处理 |
|---|---|
| 整屏纯色或近似纯色 | 不投票、不引用，直接 `Fill`。持续如此则报 `BlankFrame` |
| 重复图案（棋盘格、等高且内容相同的条目） | 多个 dy 得票接近 → 投票不成立。有预期位移时走验证路径不受影响；没有时这一帧按无位移处理 |
| 同一帧里既滚动又有原地变化 | 先认位移，剩下的差异按原地变化处理 |
| 图片渐进加载 | 每次变化是 Overlay；稳定后 `Commit`。不要对中间状态登记精灵 |
| 矩形一半是图一半是字 | 按 A11y 图片矩形切开分别编。没有 A11y 时按块统计切 |
| A11y 说是图片，像素却是纯色或少色 | 以像素为准，走 Palette |
| 很小的变化（光标） | 一个小 `Overlay`，不触发其他逻辑 |
| 转圈、进度条 | 一直是 Overlay，按 `idle_fps` 限速 |
| 整块内容横移或竖移（展开 / 收起一段） | 剩余差异里用行引用能找回大部分；找不回的按字面量发 |
| 编码耗时超过帧间隔 | 不排队：这一帧编完后直接取最新帧 |

## 12. M5 用消融决定去留的项

逐项开关，在同一批录制上看下行字节和编码耗时的变化，收益不明显的不进默认配置：

- 跨页引用（返回栈）
- 以变化前内容作 zstd 字典
- 页级共享调色板（主色、表面色变体先入表）
- 页内 zstd 长窗口（同一页连续的 `Lit` 共用压缩上下文）
- 按列带的引用（图标列、文本列分别匹配）
- 周期性动画的帧登记为精灵，循环时只发 `Copy`
- 字形级精灵（按连通域 hash 文字）
- 图片换别的有损编码
- 块级内容寻址索引（按条目间空白行切块）：零散段已按行 hash 复用，这里只评估是否还需要更粗粒度的索引

## 13. 视频区（M6）

- 判定：没有输入时持续变化的矩形（按块统计变化频率），且不是小面积的转圈。
- 该矩形成为 `Video` 区域：从画布里挖掉，B 用硬件编码器只编这个矩形，走 `video` 流；A 用 WebCodecs 解码后贴在该区域。
- 过期的视频帧直接丢，不重传。
- 其余区域照常走无损路径，不受影响。
- 区域停止变化一段时间后变回普通区域，补发一次无损内容。
