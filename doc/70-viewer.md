# 70 · A 端 WebUI

本篇回答：页面怎么启动；每种输入映射成什么；画面按什么顺序合成；返回和浏览器 history 怎么对应；l / r 调试面和 OPFS 怎么组织。

## 1. 启动

1. 页面是静态单页，由 HTTPS 源托管；开发时由 A 本机的静态服务器提供（README 给 oneliner）。必须是安全上下文（HTTPS 或 `http://localhost`），否则 WebTransport 和剪贴板不可用。
2. 从 URL 的 `#` 后读出 B 的地址、证书 hash、token（[50](50-protocol.md) §5）。缺任何一项 → 显示说明页。
3. 打开 OPFS，读出 `cache_id` 和 `cache_rev`（没有就新建）。
4. 用证书 hash 连 WebTransport → `Hello` → 按 `Welcome` 对齐缓存。
5. 右上角的包名选择器列出 `Welcome.apps`。选一个 → `Open`。URL 里带 `app=` 时自动打开。
6. 换 App = `Close` 再 `Open`。

线程分工：

| 线程 | 做什么 |
|---|---|
| 主线程 | DOM、输入、视口动画、合成（Canvas 2D） |
| Worker | WebTransport 读写、rd.wasm 解码、画布像素（RGBA 分块）、OPFS |

Worker 把视口附近的画布分块转成 `ImageBitmap` 交给主线程。解码再慢也不会卡住本地滚动。

## 2. 输入映射

| 输入 | 条件 | 动作 |
|---|---|---|
| 左键单击 / 单指轻点 | — | `Tap` |
| 按住不动 | 超过长按时间 | `LongPress` |
| 左键拖动 / 单指拖动 | 起点在 `Scroll` 区域且以纵向为主 | 本地滚动（带惯性） |
| 同上 | 其他情况（滑块、横向滑动、非滚动区） | `Touch` 流 |
| 滚轮 | 光标在 `Scroll` 区域上 | 本地滚动 |
| 滚轮 | 其他 | `Wheel` |
| 拖自绘滚动条 | — | 本地滚动（跳转） |
| 右键、Esc | — | 返回（§4）。右键菜单要屏蔽 |
| 浏览器后退 | — | 返回（§4） |
| 可打印字符、输入法上屏的文字 | — | `Text` |
| 方向键、回车、退格、Tab 等 | — | `Key` |
| Ctrl+C / Ctrl+X | — | 把按键发给 B；B 的剪贴板变化后回 `Clip`，A 写入本机剪贴板 |
| Ctrl+V | — | 在 `paste` 事件里拿到文本 → `ClipSet` → 再把 Ctrl+V 发给 B |
| `l`、`r` | B 上**没有**可编辑焦点（`Focus{editable: false}`） | 开关调试面（§5） |
| Alt+L、Alt+R | 任何时候 | 同上 |

- 坐标换算：屏幕点 → 命中哪个区域 → `Pt{region, x, y}`。`Scroll` 区域里 y 加上视口偏移变成内容坐标。命中顺序和合成顺序相反（最上层优先）。模态页打开时，点在模态页 `rect` 之外也照常发给 B（App 自己决定是否关闭）。
- B 上有可编辑焦点时，所有可打印键都是文本，不触发调试键。
- 写本机剪贴板可能被浏览器拒绝（需要权限或最近的用户手势）。被拒时显示一个“点此复制”的小提示。
- 按下反馈：`Tap` 发出时在点击处画一个短暂的圆点，B 的画面更新到达或超时后消失。
- 断线、几何切换期间输入怎么办：断线时禁用输入；几何切换对 A 不可见，照常发，B 会排队。

## 3. 合成

只在有变化时重画（收到 `Tx`、视口动了、调试面变了）。顺序自下而上：

1. 返回栈里最上面的**非模态**页：
   1. `Scroll` 区域：按视口 y 从画布取行；缺行画占位。滚动条窄带未补写时用左邻列颜色填。
   2. `Fixed` 区域：按锚（贴顶 / 贴底 / 无）和 z 序摆放。压在滚动区上面的（FAB、吸顶标题）后画。
   3. 该页的 Overlay：带内容坐标，跟着滚动区走。
2. 其上的每个模态页，依次：铺 `dim` 颜色 → 在 `rect` 画模态页（同样是区域 + Overlay）。
3. 本地反馈：按下圆点、自绘滚动条、“连接中 / 已断开”提示。
4. 调试遮罩（r）。

画布存储：每张画布按固定行数切成分块。Worker 里是 RGBA（`Copy` 的源必须可读）；主线程只持有视口上下若干屏的 `ImageBitmap`。返回栈上的页保持加载，其他页按需从 OPFS 读、按 LRU 释放。

临时页（`Page{temp}`）和普通页一样合成，只是不写 OPFS；被正式页替换后保留到下一个 `Tx` 应用完再释放（正式页的内容要从它 `Copy`）。

显示缩放：画面按 1:1 设备像素显示时文字才是锐利的。窗口放不下就等比缩小，并在面板上标出当前缩放比例。窗口尺寸变化只改显示缩放，不通知 B。

## 4. 返回与 history

A 维护两样东西：返回栈（PageId 列表，镜像 B）和 `depth`（我们往浏览器 history 里压了几层）。

**对齐函数**（每次返回栈变化后调用一次）：

- 栈深 > `depth` → `pushState`，直到相等；
- 栈深 < `depth` → `history.go(差值)`，并记一个“这次 popstate 是自己触发的”标记；
- 相等 → `replaceState`（更新标题之类）。

有了它，下面各种情况都不需要单独处理 history：

| 事件 | A 做什么 |
|---|---|
| `Page{Push}` | 入栈 → 对齐 |
| `Page{Replace}` | 换栈顶 → 对齐 |
| `Page{Pop}` | 弹到目标页 → 对齐。和乐观显示的一致时等于什么都没变 |
| 栈顶是临时页时收到正式 `Page` | 先弹掉临时页，再按它的 op 处理 → 对齐 |
| 用户按 Esc / 右键 | 立刻弹栈显示上一页 → 发 `Back` → 对齐 |
| 用户按浏览器后退（`popstate`，且没有自触发标记） | `depth` 减一 → 立刻弹栈显示上一页 → 发 `Back` |
| 浏览器前进 | 不支持：发现 `popstate` 是往前走就退回去 |

- `at_root` 为真时按 Esc：弹确认框“退出该 App？”。确认 → `Close`，回到选包界面。浏览器后退在根页面会离开页面，这是预期行为。
- 模态页同样占一层。
- 乐观显示的上一页不在缓存里（被淘汰了）→ 显示占位，等 B 的内容。

## 5. 调试面

**l 键：左上角图层-比重面板**（可折叠）

- 三层（bg / lit / fg）的字节与占比条，最近若干秒和会话累计。
- 省流分项：精灵缓存、滚动、长截屏（页面缓存）、行引用，各省了百分之多少。
- 当前页：PageId 短码、是否临时页、区域列表、`map_exact`、视口位置与采集头位置、加高状态与最近 resize 耗时、是否 `live`。
- 对这个 App 的自适应判断（[50](50-protocol.md) §6）：A11y 是否可用、采集头用滚轮还是拖动、是否允许加高、图片占比、典型滚速。
- 链路：下行码率、可绘制耗时、未确认字节、白块累计。
- 参数控件：按 `Params` 自动生成；可切换作用范围（全局 / 当前 App / 当前页）。每层的质量项在这里调。
- 开关：minimap（默认关；[20](20-pages.md) §4）；点击缩略图某处发起远跳。
- 按钮：导出长截屏（把当前页某个 `Scroll` 画布导出成 PNG，没有内容的行留透明；零散段各自导出，不与主画布拼接）、清空缓存、断开重连。

**r 键：遮罩，循环切换**

1. 关。
2. 最近刷新的矩形：每个 Op 的目标矩形描边，按类型着色（字面量 / 图片 / 引用 / Overlay），随时间淡出。
3. 图 / 文 / 视三类区：按每个像素最后一次写入时的层着色。

这两张图是给用户验证“划分得对不对”的，要能和画面一起滚动。

## 6. OPFS

```
hj/<cache_id>/
  index.json                 # cache_rev、页列表（PageId、rev、最近使用、字节数）、精灵表
  pages/<PageId>/meta.json   # 区域、known 范围、rev
  pages/<PageId>/<region>/<分块号>.bin   # 无损压缩的像素分块
  sprites/<hash>.bin
```

- 写盘在 Worker 里做。时机：页面空闲时、离开该页时、**重连握手之前**。
- 每次写盘：写改过的分块 → 写该页 `meta.json` → `cache_rev` 加一 → 写 `index.json` → 回 `Persisted{page, rev, cache_rev}`。
- `index.json` 最后写。写到一半被关掉 → 下次启动时 `meta.json` 的 rev 和 `index.json` 对不上的页直接删。
- 读分块失败 → 删该页，`Forget`。
- 容量按 `cache_mb`，按页 LRU 淘汰，淘汰时 `Forget`。返回栈上的页不淘汰。
- OPFS 不可用或配额不足 → 退化成纯内存缓存，面板上提示；功能不受影响，只是刷新后要重新下载。

## 7. 边界情况

| 情况 | 处理 |
|---|---|
| 标签页切到后台 | 停止合成；`View` 不再发；B 侧预取自然停下。切回来重画一次 |
| 断线 | 画面保留，可以继续本地滚动浏览已缓存内容；输入禁用并显示“重连中”；退避重连 |
| 收到 `Replaced` | 显示“已在别处打开”，不自动重连 |
| `Fault{Stale}` | 把刚更新的区域闪一下，提示再点一次 |
| `Fault{OffSession}` | 提示“该操作超出会话允许的应用范围，已返回” |
| `Fault{BlankFrame}` | 提示“B 端画面为空（受保护内容或 App 未启动）” |
| 无法应用某个 `Tx` | [10](10-dataflow.md) §7 的 `Resync` 流程 |
| 手机浏览器 | 单指映射同上；双指缩放只改显示缩放。打开的是同一个 HTTPS 托管页 |
| 设备像素比不是整数 | 文字会被重采样而发虚。面板提示，并提供“1:1 显示”开关 |
| 解码中用户已滚走 | 照常应用。占位是否消失只看画布有没有内容 |

## 实现备注（M1）

- `viewer/main.ts` 全在主线程（Worker / OPFS 是 M3）；wasm 里存画布和“层”平面，JS 按脏矩形 `putImageData`。`window.__hj` 暴露状态给自动化测试（`S`、`sendUp`、`canvasHash`）。
- 解码顺序：`tx` 流上的消息串行应用；`Opened`（ctl）可能晚于第一批 `tx` 到达，先攒着。每个 `Tx` 应用完（含图片异步解码写回）才回 `Ack`。
- 输入：按下 / 抬起决定动作——抬起前没动就是 `Tap`，按住 500 ms 不动发 `LongPress`，移动超过 8 px 进入 `Touch` 流（M1 没有本地滚动，所有拖动都走 `Touch`）；`Wheel` 的 dx / dy 是“格”（deltaY / 100）。可打印字符经隐藏 textarea 的 `input` 事件成 `Text`（IME 上屏也走这里），`Focus{editable:false}` 时忽略。
- 返回历史对齐（§4）、`at_root` 确认框、乐观上一页是 M3；M1 的 Esc / 右键只发 `Back`。
- 本地网络访问（Chrome 147+）与 HTTPS 托管页没测；页面用 `http://localhost`。
