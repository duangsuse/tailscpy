# 10 · 数据流与状态归属

本篇回答：一帧、一次点击、一次滚动各走哪几步；每份状态归谁；断了怎么恢复。
A = 浏览器，B = Android。消息名见 [50-protocol](50-protocol.md)。

## 1. 下行：B 的一帧 → A 的像素

| 步 | 在哪 | 输入 | 输出 |
|---|---|---|---|
| 1 采集 | host-adb | 虚拟屏 | RGBA 帧、帧时间戳、采集几何（1× 或加高） |
| 2 结构 | host-adb → rd | A11y 树、A11y 事件、Activity 栈 | 页面候选、区域候选（都带时间戳） |
| 3 识别 | rd | 帧、B 上一帧的行 hash、结构候选 | 当前页、各区域 rect、滚动区位移、采集头位置 |
| 4 比对 | rd | 当前帧的行 hash、该页画布的行 hash 表 | “A 缺的矩形”列表 |
| 5 编码 | rd | 缺的矩形的像素、可引用的内容、精灵表 | 一个事务 `Tx` |
| 6 发送 | host-net | `Tx` | 下行流 `tx` |
| 7 解码 | viewer（rd.wasm） | `Tx` | 写入页面画布、精灵池、Overlay 表 |
| 8 合成 | viewer | 画布、Overlay、A 自己的视口 | 屏幕 |
| 9 确认 | viewer → B | — | `Ack`（已应用）、`Persisted`（已落盘） |

四条必须守住：

- 第 4 步比对的是“A 已有的内容”（B 存的该页行 hash 表），不是 B 的上一帧。上一帧只在第 3 步用来求位移。
- B 只处理最新一帧。发送拥塞或编码来不及时，中间帧直接丢。因为比对基准是 A 的状态，丢帧不会出错。
- 下行的画面数据只有一条有序流。A 按到达顺序应用，所以 B 发出去的内容可以立刻当作后续 `Tx` 的引用源，不用等确认。
- 一个 `Tx` 在 A 端原子生效：全部 Op 应用完才合成一次。

## 2. 上行：A 的输入 → B 的动作

| A 的输入 | A 本地立刻做 | 发给 B | B 做 |
|---|---|---|---|
| 滚动（滚轮 / 拖动 / 滚动条） | 改自己的视口，用画布合成 | `View`（只保留最新值） | 调度采集头（[30](30-scroll.md)） |
| 点按、长按 | 画一个按下反馈 | `Tap` / `LongPress` | 采集头就位 → 校验 → 注入 |
| 非滚动区拖动 | 无 | `Touch` 流 | 原样注入 |
| 返回 | 立刻显示返回栈上一页 | `Back` | 注入 BACK → 发 `Page{Pop}` 确认或纠正 |
| 按键 / 文本 / 剪贴板 | 无 | `Key` / `Text` / `ClipSet` | 注入 |
| 调参 | 更新面板 | `Tune` | 改参数表，下一帧生效 |

## 3. 状态归属

| 状态 | 归谁 | 落盘 | 丢了怎么办 |
|---|---|---|---|
| 页面画布像素、精灵像素 | A | OPFS | 该页重新下载 |
| 每页每区域的行 hash 表、精灵 hash 表（= B 认为 A 有什么） | B | `/data/local/tmp/hj/` | A 的整个缓存作废（`Welcome{Reset}`） |
| A 的视口位置 | A | 否 | 进页时用 B 给的初始位置 |
| 采集头位置、采集几何 | B | 否 | 用画布对齐重新求 |
| 返回栈（PageId 列表） | B 为准，A 镜像 | 否 | B 重发 `Page` |
| Overlay 表 | 两端各一份 | 否 | 断线即清空 |
| 参数表 | B | 是（全局 + 按 App + 按页） | 用默认值 |
| 被改过的系统设置的原值 | B | 是，改之前先写 | 下次启动补还原 |

B 对“A 有什么”的认识只有两个来源：同一连接内，发过的就算（有序流保证 A 会按序应用）；跨连接，只认 A 握手时报的版本。细节在 [20](20-pages.md) §7。

## 4. 一次滚动

1. 用户滚 → A 立刻移动视口。画布里有的行直接画，没有的行画占位。
2. A 发 `View{region, y, vy}`。
3. B 调度采集头：先补 A 视口里缺的行，再补运动方向前方的行。
4. B 每注入一步滚动得到一帧 → 求位移 → 找出 A 缺的行 → 编码 → 发送。视口内的先发，预取的后发。
5. A 收到 `Tx` → 写画布 → 重新合成 → `Ack`。

来回滚已有内容时第 3 步无事可做，下行为零。

## 5. 一次点击

1. A 发 `Tap`，坐标是内容坐标（页、区域、x、y），不是屏幕坐标。
2. B 把采集头移到能看见该点的位置（加高模式下通常已在范围内）。
3. B 比对点击处那个条目的行 hash 与画布记录：
   - 一致 → 换算成当前采集几何下的屏幕坐标，注入点按；
   - 不一致 → 不点，补发差异，回 `Fault{Stale}`。A 闪一下更新的区域，用户再点一次。
4. 之后的帧照常走下行。换了页 → [20](20-pages.md) §2。

## 6. 节拍、优先级、背压

- 采集回调来帧才干活；没有新帧就是零流量。不要用定时器驱动编码。
- “稳定”“空闲”都用帧时间戳和输入时间戳判断，不读墙钟。这样离线重放同一份录制会得到相同结果。
- 下行流不可写，或未确认的字节超过上限时，不编码；等恢复后拿最新帧编一次。
- **可见区永远优先**：预取只在“视口内没有活要干”时进行，一次只发一小段，并且在途（已发未确认）的预取量有上限（`pre_inflight_ms`，按当前码率折算成字节）。于是一次点击的画面更新最多被一小段预取数据挡住。
- 有输入到达时立刻停止预取，直到这次输入引起的画面更新发完。

## 7. 失败与恢复

| 情况 | 谁发现 | 处理 |
|---|---|---|
| A 无法应用某个 `Tx`（解码失败、引用的内容不存在） | A | 清空该页，发 `Resync{page}`，并丢弃该页后续的 `Tx`，直到收到 B 的 `PageReset{page}`。B 清空该页的行 hash 表，把该页引用过的精灵也当作 A 没有，发 `PageReset{page}`，然后重发视口内的内容 |
| 连接断开 | 两端 | A 退避重连；B 保留虚拟屏和 App 一段时间；重连后走握手对齐（[50](50-protocol.md) §3） |
| 旧连接还在，新连接进来 | B | 给旧连接发 `Replaced` 后关闭它。收到 `Replaced` 的一方不自动重连 |
| B 进程重启 | A（重连时看 `Welcome`） | hash 库还在 → 正常对齐；不在 → `Reset` |
| A 刷新页面 | — | 等同断线重连；画布从 OPFS 按需加载 |
| 采集几何变化（加高 / 缩回） | B | 变化期间不发 `Tx`；稳定后用画布对齐重求采集头 |
| App 崩溃或退到桌面 | B（栈顶变化） | 结束会话，`Fault{AppGone}` |
| 栈顶离开白名单 | B | 注入 BACK，`Fault{OffWhitelist}` |
| 帧几乎是纯色（内容受保护，或 App 没拉起来） | B | `Fault{BlankFrame}`，A 提示，不写画布 |
| A 的窗口尺寸变了 | A | 只做显示缩放，不改虚拟屏尺寸 |
