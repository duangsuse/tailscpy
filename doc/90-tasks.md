# 90 · 任务顺序（给执行者）

按顺序做。每项先读“读”一栏的文档，再动手。做完按“怎么确认”一栏实际跑一遍、看到结果，才算完成。

## 0. 通用规则

1. 规则以 [GOAL](../GOAL.md) §3 的六条为准。文档没写清楚的地方，选不违反这六条的最简单做法，并在对应文档末尾的“实现备注”里记一行。
2. 平台行为和文档不一致时，以真机实测为准：先更新 `doc/probe-<设备>.md`，再按该探针的“不通过时”一栏走。
3. 阈值和开关一律进参数表（[50](50-protocol.md) §6），不写死在代码里。
4. `rd` 里不读墙钟，不做 I/O。时间从帧和输入的时间戳来。这是 bench 能重放的前提。**区域/语义侦测**（`region.rs`）和**启发式/规则集合**（`heuristics.rs`，含精确滚轮公式、预测滚动等）各自放进单独文件，不要散落在状态机或编解码里。
5. 每加一个工具或入口，就把它的 oneliner 补进 `./README.md`。
6. 从 M2 起，每个里程碑结束时跑一次 bench，把报表目录写进提交说明。
7. `old/`、`old-ov/` 只是经验参考，不要照搬它的结构（它是“整屏对上一帧”的模型）。`cmp-scp/` 是对比用的 scrcpy 中继，不要改。

不要做的事：

- 不要用定时器驱动采集或编码；没有新帧就什么都不做。
- 不要把 A 的拖动、甩动原样转发成 B 的触摸滑动（滚动区内）。
- 不要因为 A11y 没到就不出图。
- 不要拿 B 的上一帧当编码基准；基准是该页的行 hash 表。
- 不要给画面数据开第二条流。
- 不要露一行同步一行；采集头一步走大半屏。
- 不要改 [60](60-host.md) §2 表格之外的系统设置。
- 不要加文档没要求的兼容层、回退路径或抽象（例如 WebSocket 回退）。

**调试过程里查出并修掉的编码器 bug（都有回归测试）**：① Overlay 之后改走画布时，拿“上一帧”当 A 的版本收窄列范围，导致 B 记了 `known` 却没发像素（A 缺内容，Verify 报错）→ 在内行变化一律整行发；② 压后期间的条带去重表在换页 / Clear / 提交后没清，导致新页的同样条带被当成“已发过”跳过；③ 同一块 JPEG 在“同一行别的部分被压后”期间每 50 ms 重发一次（NewPipe 首屏 5 MB → 0.4 MB）；④ 虚拟 A 把上一次附着遗留在队列里的消息应用到新状态上。
