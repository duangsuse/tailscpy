# 20 · 页面、区域、画布、缓存

本篇回答：屏幕内容怎么切成可缓存的对象；什么时候算换页；缓存怎么落盘、怎么对齐。

## 1. 对象

| 对象 | 是什么 | 谁有像素 |
|---|---|---|
| 会话 | 一块虚拟屏 + 一个白名单 App | — |
| 页面 Page | App 的一个界面，用 PageId 标识 | — |
| 区域 Region | 页面里的一个矩形。`Fixed` 不滚；`Scroll` 纵向滚动；`Video` 持续变化（M6） | — |
| 画布 | 每个区域一张。`Fixed` 的画布就是它的矩形；`Scroll` 的画布是一张按内容坐标寻址的长截屏 | A |
| 行 hash 表 | 每张画布每行一个 hash，没见过的行为空 | B |
| 精灵 Sprite | 按内容 hash 存的小图：无损（返回键、开关）或有损（图片）。跨页共享 | A（B 只有 hash） |
| Overlay | 浮在最上面的临时补丁，不进画布 | A |

一个用久了的 App，就是一棵由长截屏组成的树。

## 2. PageId 与换页

`PageId = hash(包名, Activity 类名, 窗口标题或顶栏标题文本, 骨架, 几何键)`

- 骨架：把 A11y 树每个节点的（class、resource-id）按树形序列化。遇到回收型列表容器（RecyclerView、ListView、GridView）只记容器本身，不进子树——列表项的数量和内容不该影响页面身份。
- 几何键：虚拟屏宽、dpi、字体缩放、深浅色。换几何 = 换一套缓存。
- PageId 只用来找缓存候选。是不是真的同一页由像素决定：进入后固定区和首屏的行 hash 与记录对不上的部分，按差异重发。

何时算“疑似换页”（每帧检查，满足其一）：

- A11y 报窗口状态变化，或栈顶 Activity 变了；
- 大部分行都变了，而且不是滚动能解释的。

疑似换页之后：

1. 等 A11y 树，最多 `a11y_wait_ms`。
2. 等到 → 算 PageId → 发 `Page`。A 有这页缓存就立刻显示，B 只补差异。
3. 没等到 → 先发一个**临时页**（`Page{temp: true}`，整屏一个 `Fixed` 区域，不缓存、不落盘），让用户先看到。
4. 树到了 → 发正式的 `Page{op: Replace}`。正式页缺的内容用 `Copy` 从临时页搬过去，不重发像素。A 把被替换掉的临时页保留到下一个 `Tx` 应用完再释放。
5. 树一直不来 → 临时页一直用着。功能正常，只是这一页没有缓存和滚动优化。

## 3. 区域怎么来

1. **A11y 提案。** 可纵向滚动的节点 → `Scroll` 候选。其余部分按“在滚动区上方 / 下方 / 压在滚动区之上”切成 `Fixed`。
2. **像素确认。** 第一次滚动时，`Scroll` 区内的行应整体平移，区外的行不动。不符合就以像素为准修正，并发 `Regions`。例如滚动区里有一块不跟着动，那是压在上面的 `Fixed`（FAB、吸顶标题）。
3. **没有可滚动节点** → 整页一个 `Fixed` 区域。

约定：

- `Region.rect` 永远用 1× 视口坐标。B 处于加高几何时负责换算（[30](30-scroll.md) §5）。
- `Fixed` 区域带锚（贴顶 / 贴底 / 无）和 z 序，A 按锚摆放。
- 嵌套滚动（外层 ScrollView 套内层列表）：只取面积最大的那条纵向滚动链做 `Scroll`，其余算内容。
- 横向滚动容器在 M6 之前当普通内容处理。

## 4. Scroll 画布的坐标

- 内容坐标 y：第一次进入该页时，区域顶边对应 y = 0，向下为正。可以为负（进来时不在顶部，后来又往上滚）。
- `known = [y_min, y_max)`：已有内容的范围，中间允许有洞。`at_top` / `at_bottom`：是否已探到内容的头 / 尾。
- `start_y`：这次进入页面时 App 实际显示的位置。A 把视口放到这里。
- **重进页面时滚动位置可能不同**：B 拿首帧滚动区的行 hash 和该页行 hash 表做一次对齐（和求位移是同一个算法，[40](40-codec.md) §3），得到采集头的 y。对不上 → 这个区域的画布清空重来（`Clear{region}`）。
- `map_exact`：位移每一步都验证通过时为真。条目等高、内容不变的列表，地图是精确的。出现对不上的情况（中间插入 / 删除、条目高度变化、像素位移与 A11y 的滚动量不一致）就置假。置假后采集头始终跟随 A 的视口，直到离开该页；画布里已有的内容仍然可以被 `Copy` 引用，所以流量不会退回到全量。

## 5. Overlay：短暂变化不进画布

来源：按下高亮、涟漪、光标闪烁、toast、加载转圈。

规则：画布里原本有内容的地方发生原地变化，先发 `Overlay`（带区域和内容坐标，所以会跟着内容滚）。之后三选一：

| 之后发生 | 处理 |
|---|---|
| 变回原样 | `OverlayDrop` |
| 稳定超过 `commit_ms` | `Commit`：A 把 Overlay 像素写进画布，B 更新行 hash，`pg_rev` 加一。不重发像素 |
| 一直在变（转圈、闪烁） | 保持 Overlay，按 `idle_fps` 限速更新，永不 `Commit` |

断线或换页时两端清空 Overlay 表。

## 6. 返回栈

B 维护 PageId 栈，A 镜像一份并同步到浏览器 history。

`Page.op` 怎么定：

| 这次换页的起因 | op |
|---|---|
| Back | 新 PageId 在栈里 → `Pop` 到它；不在 → `Replace` 栈顶 |
| 其他输入，且 Activity 没变、栈深没变、顶栏没变（tab 切换这类平级变化） | `Replace` |
| 其他输入 | `Push` |

- **模态页**：弹窗、菜单、底部面板是 `Page{modal: Some{rect, dim}}`。A 的画法：下面那一页保持不动 → 盖一层 `dim` 颜色 → 在 `rect` 画模态页。Back 关掉它就是 `Pop`。
  - 判定：A11y 报出一个比屏幕小的新窗口，或者新画面里有一个矩形之外的部分等于“上一页整体变暗”。
  - `dim` 由 B 从像素求出（矩形之外 = 上一页与某个颜色按固定比例混合）。求不出来（背景被模糊了、不是均匀压暗）→ 不当模态页，按普通页整屏发。
  - 压暗后的背景在 A 上是算出来的，和 B 可能差在取整上。校验时跳过这部分。
- **乐观返回**：A 收到 Esc 立刻显示栈上一页（来自缓存），再发 `Back`。B 的 `Page{Pop}` 到了之后如果 PageId 不一样，A 以 B 为准。
- **根页面**：在根页面返回会让 App 退出。`Page.at_root` 为真时 A 弹确认框，不直接发 `Back`。

## 7. 持久化与版本

A（OPFS）存像素，B（`/data/local/tmp/hj/`）存 hash。两边都以页为单位。

**B 的行 hash 表分两层：**

- `base`：A 已确认落盘的状态，版本 `base_rev`；
- `pending`：已经发出、但 A 还没确认落盘的改动，按 `pg_rev` 记。

比对“A 缺什么”时看两层叠加的结果。

**版本怎么走：**

- `pg_rev`：B 每发出一个改动该页画布的 `Tx` 就加一，随 `Tx` 下发。只有 Overlay 的 `Tx` 不改版本。
- A 在页面空闲时、离开该页时、**重连握手之前**把改过的页写盘，然后回 `Persisted{page, rev, cache_rev}`。
- B 收到 `Persisted{page, rev}` → 把 `pending` 里不超过 rev 的改动并入 `base`。
- `cache_rev`：A 每次写盘加一的计数。B 记住最后收到的那个值。

**握手对齐：**

| 情况 | 处理 |
|---|---|
| `cache_id` 相同，`cache_rev` 相同 | `Keep`。A 的盘上状态就是 B 的 `base`；B 丢掉全部 `pending` |
| `cache_rev` 不同 | `NeedInventory`：A 上报（PageId, rev）清单，逐页处理：rev 落在该页 `base_rev` 到已发出的最新版本之间 → 并入不超过它的 `pending`，丢掉其余；否则该页两端都删（B 用 `Purge` 告诉 A）。清单里没有、B 却有记录的页，B 自己删 |
| B 没有这个 `cache_id` 的记录 | `Reset`：A 清空缓存 |

`pending` 和 `base` 一起落盘；B 重启后 `pending` 丢了也没关系，对不上的页会在握手时被删。

**淘汰：** A 按页 LRU，容量 `cache_mb`。淘汰某页时发 `Forget`，B 同步删。临时页和 Overlay 从不落盘。

**精灵：** 跨页共享，所以单独对齐。

- B 的精灵表和行 hash 表一样分 `base` / `pending`，随 `Persisted` 推进；握手得到 `Keep` 时同样丢掉 `pending`。
- A 写盘时先写精灵，再写引用它的页。盘上的页引用的精灵一定在盘上。
- 握手走 `NeedInventory` 时，A 连同精灵 hash 清单一起上报，B 的精灵表以它为准。
- 淘汰：没有页引用且总量超过 `pool_mb` 时，由 B 决定并下发 `SpriteDrop`。A 不自行删精灵。
- A 发现引用的精灵不存在 → 走 `Resync`（[10](10-dataflow.md) §7）。

## 8. 新鲜度

- 默认 `static`：来回滚动、返回上一页都直接用缓存，B 不为此专门重采。采集头空闲时会停回 A 的视口（[30](30-scroll.md) §4），那时看到的差异照常下发，等于免费校验。
- 按页或按 App 可设 `live`：采集头始终跟随 A 的视口，变化立即下发。
- 没有输入却持续变化的区域，自动按 `idle_fps` 限速。

## 9. 边界情况

| 情况 | 处理 |
|---|---|
| 两个不同页面算出同一个 PageId | 按像素差异重发，功能正确，但两页会互相覆盖缓存。发现后把能区分它们的文本加进 PageId |
| 同一页面内容变了（列表多了一项） | 可见处按差异重发，`map_exact` 置假 |
| 图片异步加载，先占位后出图 | 原地变化 → Overlay → `Commit` |
| 页面还在加载就被采到（骨架屏） | 同上，稳定后 `Commit` 覆盖 |
| 转场中间帧 | 系统动画已关，通常没有；出现了也会被“等稳定”吸收 |
| 进入页面时已经带着弹窗 | 先 `Push` 页面，再 `Push` 模态页 |
| A 缓存里有、B 记录里没有的页 | 握手时删掉 |
| 字体、深浅色、屏幕宽度变了 | 几何键变 → 新的一套缓存；旧的按 LRU 淘汰 |
| 断线时有 `Tx` 还在路上 | A 没收到的那些留在 B 的 `pending` 里，握手时按 A 报的 rev 丢掉 |
| A 刷新时还有没写盘的改动 | A 盘上是旧版本；握手时 B 按那个版本回退，只重发差的那部分 |
