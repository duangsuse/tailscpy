# 25 · tile 地图（内容空间）

> 目标：**两端用同一种直觉完成滚动缓存**，长截图 = 导出 tile 地图的内部状态。

## 1. 问题

老做法是"纵向按行的 hash + COPY"：

- 滚动靠**行哈希投票**找位移；不是刚性平移就整屏退化��字面量。
- A 端只保留**视口大小**的一帧缓冲 + 几帧历史 → 往回滚只能靠 B 重发。
- 长截图是 B 端事后按内容坐标拼像素行 → 拼的是"行"，不是明确的 tile 状态；边界会露缝。

## 2. 模型：屏幕是一张 tile 地图

| 概念 | 含义 |
|---|---|
| **内容坐标** | 内容在"无限画布"上的位置（内容行号，可负）。与屏幕位置无关 |
| **原点 origin** | 本帧**屏幕第 0 行**对应的内容行号。每一帧都带（帧头里） |
| **tile** | 内容坐标上的一块（当前实现是**整行**：池里的条带，或字面量行） |
| **视口** | 原点 + 尺寸（就是虚拟屏） |

于是：

| 现象 | 在 tile 地图里是什么 |
|---|---|
| 滚动 | **只有原点变**，tile 不动 → 不重发像素 |
| 滚回来 | 同一个内容坐标 → 同一个 tile → 直接命中 |
| 同一段内容出现两次 | tile id = 内容哈希 → 自动去重（两端各自算，结果一致） |
| 长截图 | 把内容空间里的 tile 拼起来 |

## 3. 帧格式

```
frames 通道一条消息：
  fid u32 小端 | flags u8 | epoch u32 小端 | origin i64 小端 | 操作流
```

- `origin` = 这一帧的内容原点（屏幕第 0 行 = 内容第几行）。
- `epoch` = **内容空间代号**：B 换页时递增，A 端发现代号变了就**清掉自己的地图**
  （否则两个坐标系的行会混在一起，长截图就不准了）。真机上踩过这个坑：
  换页后原点跳变，A 端地图里新旧两套坐标混排，长截图顶部对不上实时画面。

两端据此维护同一张地图。

操作码不变（1 FRAME_REF / 2 COPY / 3 SPRITE_REF / 4 LIT / 6 FILL / 11 RETAIN / 12 DROP），
但**每个操作的内容坐标 = 屏幕坐标 + origin**，于是：

| 操作 | 内容空间里发生什么 |
|---|---|
| `RETAIN id y h` | 把**上一帧**的屏幕行 y..y+h 登记为条带 → 内容行 = prev_origin + y .. |
| `SPRITE_REF id sy h dy` | 条带的行摆到屏幕行 dy.. → 内容行 = origin + dy ..，tile = (id, 行号) |
| `COPY sx sy dx dy w h` | 上一帧的 sy.. 搬到本帧的 dy.. → 内容行 src = prev_origin + sy，dst = origin + dy；**两者相等 = 纯滚动**（tile 不变）；不等 = 内容变了（那一行按字面量快照） |
| `LIT x y w h` | 新像素 → 内容行 origin + y ..，整行快照进地图 |
| `FILL x y w h` | 同上（整行快照，填色只占一部分行宽也按整行记） |
| `FRAME_REF b` | 回到历史第 b 帧 → **连原点一起还原**（内容坐标是帧的一部分） |

## 4. 两端各维护什么

| 端 | 状态 | 用途 |
|---|---|---|
| B（编码器） | `canvas.o`（原点）+ 画布跨度表（内容坐标 → 条带 id）+ 精灵池 | 编码：贴回、返回缓存、淘汰顺序 |
| A（解码器） | `TileMap`：内容行 → tile（条带引用 / 字面量行）+ 池 | 长截图、状态导出、滚动缓存自检 |

A 端的 `TileMap`（`codec/src/tile.rs`）：

- 内容行 → `Tile::Strip{id, row}`（池里的条带）或 `Tile::Lit{off}`（自己带的像素行）。
- 字面量行上限 64MB（约 1.6 万行）→ 超了就不再收（远处留空洞）。
- `summary()` 把地图压成几段（起止内容行 + 条带 id / 字面量标记）→ 就是**内部状态**。

## 5. 长截图

**规则**：长截图 = **当前视口（以实时画面为准）** + **滚出去的历史（tile 地图补）**。
视口那部分永远逐像素等于屏幕（地图里可能有空洞或旧值）；历史部分才是 tile 地图的状态。
范围 = 地图的范围 ∪ 视口范围（视口不在地图里也要占位，否则画面顶部会被裁掉）。

| 端 | 怎么来 | 导出 |
|---|---|---|
| A（客户端） | `Decoder::long_shot()`：把内容空间里的 tile 拼成一张图，视口那部分用实时画面覆盖 | mm1 查看器面板里的「长截图（A 端 tile 地图）」→ PNG + tile 地图 JSON |
| B（服务端） | `Encoder::long_shot()`（原有的画布拼接） | `POST /tune?k=longshot` → PNG |
| B 的地图状态 | `Encoder::canvas_segments()` | `GET /tilemap` → `{origin, segments:[{lo,n,id}]}` |

验收（`codec/tests/tile.rs`）：**滚完 60 行后，A 端导出的长截图必须逐像素等于原始页面**，
且地图里要有条带引用（不能全是字面量快照 = 没省缓存）。

**真机验收**（razr 40，mm1 构建）：长截图 1354 行（内容行 −154…1199），
与实时画面逐行比对 **93/93 行完全一致、0 空洞**；每帧 0px 校验 868/0。

**现在这一步是自动的**（`e2e/run.py` 每轮都做）：页面导出长截图后，在浏览器里把
「长截图里 `origin - lo` 起的那 H 行」与**实时帧缓冲**逐像素比对，行数不同就打印警告。
真机实测（settings / libchecker / audioconnect 三个 App）：
内容空间 3934 / 3505 / 1464 行，视口分别落在第 2657 / … 行，**逐像素相同 ✔**。

> ⚠️ **视口不一定在长截图的底部**：滚下去再滚回来，内容空间下方还留着旧位置的内容，
> 所以视口的行号是 `origin - lo`（元数据 JSON 里有 lo/hi/origin），不是 `rows - H`。
> 早先的代码用"视口高度"当写入行号的上界，滚久了视口那几行会被跳过 → 长截图底部变旧内容；
> 现在上界改成内容空间的总行数，并加了上面那条自动比对。

### ⚠️ 两端的「长截图」不是同一份数据（已知差距）

| | A 端（tile 地图） | B 端（`Encoder::long_shot()`） |
|---|---|---|
| 数据来源 | 完整的 tile 地图：条带 + **字面量行** | **画布（canvas）**：只有登记过的条带 + 当前这一屏 |
| 覆盖范围 | 内容空间里**记住的每一行** | 条带登记到的范围 + 当前屏（可能更短） |
| 空洞 | 视口部分永远逐像素等于屏幕 | 记不住的地方是**黑带**（`LongShot.gap` 计数，响应头 `X-HJ-Gap`，页面会提示） |
| 实测（razr 40，settings + 滚轮） | 3948 行（内容空间） | 1646–1763 行（随滚动历史变化） |

也就是说：**"长截图 = 导出 tile 地图的内部状态"这条目前只有 A 端严格成立**；
B 端还是旧的"画布 + 条带"那套，所以两份长截图**行数不一样**、内容也可能不一致。
真机验证过 B 端长截图能正常导出（540×1646 的 PNG ✔），但它不是 tile 地图的完整导出。

要补齐的话，需要给 B 端也维护一张和 A 端同构的 tile 地图（条带 + 字面量行 + epoch），
然后让 `Encoder::long_shot()` 从它导出 —— 这是**下一步的活**，不是现在的小修。

**两端对账**（**现在每次 e2e 自动做**）：e2e 跑完会同时取
「B 端 `GET /tilemap` 的内容原点 + 条带段」和「A 端长截图元数据里的 origin/lo/hi」，
原点必须一致才算两端维护的是同一个内容空间。
真机实测（razr 40，settings + 滚轮）：**B 端 origin=2034，373 个条带段；A 端 origin=2034 → 两端一致 ✔**。
假 B 端的 `/tilemap` 不维护内容坐标（条带段为 0），那种情况只打印不断言。

手工对账（浏览器里实测，`mock_b` + mm1 查看器）：

| 量 | B 端（`GET /tilemap`） | A 端（`hj_shot_meta`） |
|---|---|---|
| 内容原点 | −69 | −69 ✓ 一致 |
| 条带段数 | 348 段（每段 5 行） | 合并成 49 段 ✓ 同一批内容 |
| 内容范围 | [−100, 1604] | [−100, 1624]（多出当前视口的 20 行：B 只登记"滚过的"内容） |

## 6. 现在的边界

| 项 | 状态 |
|---|---|
| tile 粒度 | **整行**。横向偏移 / 拼图式布局表达不了（二期：2×2 行块或 16px 块） |
| 空洞 | 过度滚动拉伸、跳变 → 内容坐标上出现空洞（B 端 `canvas.lost` 会重新找原点；A 端留空洞） |
| 帧引用与地图 | `FRAME_REF` 还原屏幕与原点，但**不还原地图**（地图是"见过的内容的并集"，长截图用它更全） |
| 内存 | A 端：tile 地图上限 **32MB** 像素、精灵池硬上限 **96MB**、历史环 4 帧 → WASM 内存稳定在 **~140MB**（真机压测 30 秒连续滚轮：稳定不涨） |
