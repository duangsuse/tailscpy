# 40 · 易错点总表

按"踩过的坑"整理，每条都写清**症状 → 根因 → 处理**。

## 环境 / 进程

| 症状 | 根因 | 处理 |
|---|---|---|
| `cargo test` 报 rustdoc "failed to write arguments to temporary file / No space left on device"，`adb push` 也失败 | **`/tmp` 是内存盘（tmpfs）且被写满**（本机 7.7G；里面有一批每分钟新建的 `tmpXXXX` 目录，含模型文件，不是本项目的） | 把构建临时文件放磁盘：`export TMPDIR=$PWD/.tmp`（`mm1/check.sh` 已经这么做了）；清掉自己那部分临时产物 |
| 后台 loop 永不退出 | `pgrep -f`/`pkill -f` 的模式出现在自己命令行里 → 匹配到自己 | 模式写成 `[r]ig.py` 这样，或直接按 PID kill |

| 症状 | 根因 | 处理 |
|---|---|---|
| `pgrep -f`/`pkill -f` 的模式匹配到自己，后台 loop 永不退出 | 模式字符串出现在同一条命令的命令行里 | 用 `[r]ig.py` 这种写法，或直接按 PID kill；**模式不要出现在自己的命令行里** |
| 守护进程两次测试之间无日志消失 | `com.miui.powerkeeper` 向进程发 SIGTERM（时间吻合，未证实） | 测试前先重启 daemon；别假设它活着 |
| Android 里任意线程未捕获异常直接 kill -9 整个进程 | 系统默认 UncaughtExceptionHandler | daemon 里装自己的 handler，只记日志、让服务继续 |
| `InputManager.getInstance()` 在 app_process 里 NPE | 隐藏 API 需要系统上下文 | 用 `getSystemService`（系统上下文）拿 |
| 自建 FIFO 失败（SELinux 不让 shell 建 fifo） | 权限 | 退化成"被轮询的普通文件"：追加写命令，结果写 `ctl.<端口>.out` |
| zsh 不对变量分词（`set -- $cfg`、`$ZIG` 带空格） | zsh 默认不分词 | 用函数或 `${=var}`；或者干脆 `bash` |

## 采集 / 语料

| 症状 | 根因 | 处理 |
|---|---|---|
| 整个 App 采成纯黑 | `am start -a MAIN -c LAUNCHER -p 包` 对 Bible / ActivityLauncher 报 `unable to resolve Intent` | 用显式组件名：`cmd package resolve-activity --brief -c android.intent.category.LAUNCHER 包` |
| `screencap -d <id>` 返回 "Display Id … is not valid" | 虚拟屏被重建，SurfaceFlinger id 变了 | 采集前关掉所有连着 relay 的标签页；抓图失败时重取 id |
| 低熵画面（颜色数 ≤8） | App 没拉起 / FLAG_SECURE / 在根页面按返回退出了 App | 当场告警，不当正常数据 |
| 采集期间跑语料工具会读到半张图 | 文件在写 | 采集结束再跑 |

## 编码 / 解码

| 症状 | 根因 | 处理 |
|---|---|---|
| A 端画面与 B 不一致 | 操作序列里有"未验证"的操作 | 编码器只发已验证等于 cur 的操作；A 端出错的策略是"画面保持上一帧 + 请求 Resync" |
| 滚动没命中、整屏变字面量 | 非刚性（越界回弹）/ 动画 / 首步重绘 | 见 [20-recognition.md](20-recognition.md) |
| 滚动条区域每帧都很贵 | 滑块淡入淡出时像素全变，搬不动 | 只能字面量；`edge_copy` 只处理"跟内容走"的滑块 |
| 照片类字面量特别大 | zstd 压原始 RGB 对照片很弱 | 可逆变换（−30%）；无损 WebP（−50%，B 端慢，A 端要解码器） |
| 字面量解压后长度对不上 | 载荷被截断或编码器 id 不认识 | 解码器报 `Lit` 错误；流已失步就关流 |
| 帧缓冲哈希对不上 | 整帧哈希不是 `hash64(整帧)`，而是**各行哈希的折叠** | `hj_codec::frame_hash` / `Decoder::hash()` 两边必须同定义 |
| 返回上一页变成整屏重发 | 整页登记条件没满足（页面未稳定 ≥120ms / 不是"整页换掉"） | 看 `/stats` 的 `pool_rows`；`page_stable_ms` 可调 |

## 协议

| 症状 | 根因 | 处理 |
|---|---|---|
| 两端版本不一致就断 | `Hello.version` 不等 → `Reject{Version}` | 同一个 APK 两端一起升 `VERSION` |
| 解码流失步 | postcard 不自描述，改了变体顺序/字段 | 枚举只追加、字段不增删改序；改了就升版本并同步 golden bytes |
| ctl 上的大消息卡住触摸 | 所有消息挤一条流 | 通道分离：ctl 低频、up 高频、frames 数据面 |
| 新连接把旧连接顶掉 | 设计如此（adb 转发后可能有半开 TCP） | 客户端自己重连；`Reject::Busy` 只在明确要独占时用 |
| 左上角只读层列表全是 `0k px · 0` | 层列表只在"请求时"取一次，而那时候还没编码任何帧 | B 端每 ~0.5 秒主动推一次层列表（`Res{rid:0, LayerList}`），页面收到就刷新 |
| WebSocket 断了没重连 | 页面侧没有退避重连 | 重连要有退避与令牌刷新 |

## 时序 / 延迟

| 症状 | 根因 | 处理 |
|---|---|---|
| 后面的触摸/按键全排队 | Kotlin 命令泵睡了 | 命令泵**不能睡**；耗时手势（滑动手势、滚轮）放手势线程 |
| 输入注入后画面没变 | 注入到了别的窗口 / 屏幕没亮 | 注入要 `@Synchronized`；先 `KEYCODE_WAKEUP` |
| 测出来的延迟忽高忽低 | 统计口径混了"在途旧帧" | 只统计"回调晚于注入"的帧；`input_to_sent_ms` = 输入→它引起的第一帧 |
| 转场时延迟尖峰 | 动画期间每个画面都要走一遍编码 | 会话期间关动画（`Anim.kt`，退出恢复） |
| A 端解码慢 | 字面量太大 | 字节下降 = 解码时间下降（同一个旋钮） |
| B 端手机息屏后画面停了 | **假设未验证**（IDEA.md 的"局域网 15ms、B 屏常闭"）：虚拟屏与 ImageReader 是否在息屏后继续出帧，没量过 | 虚拟屏理论上独立于物理屏；但设备进 Doze 后可能停。测法：息屏 30s 后注入一次输入，看有没有新帧 |
| 返回上一页后，精灵池淘汰顺序乱了 | 深度标签取的是"查询时"的深度，而 `dumpsys` 是异步的 | 标签要用**输入开始时**的深度（`Encoder::set_depth(当前深度, 输入开始时深度)` 用后者）；否则返回后旧页面被判成"更深"，先被淘汰 |

## 部署 / 传输

| 症状 | 根因 | 处理 |
|---|---|---|
| 证书 14 天后连不上 | 自签证书有效期 ≤14 天 | 轮换机制还没定（配对多发几个哈希？连接内下发？） |
| 端口被别的机器抢到 | 绑了 0.0.0.0 | **只绑 Tailscale 网卡**，不得 0.0.0.0 |
| push 覆盖了正在跑的 dex | 进程正映射着那个文件 | 别往运行中实例的目录 push；测试用第二个实例（`HJDIR`/`端口`） |
| relay 把守护进程的转发也删了 | `adb forward --remove-all` | 不要用 `--remove-all` |

## tile 地图（mm1 新增）

| 症状 | 根因 | 处理 |
|---|---|---|
| 长截图顶部对不上实时画面 | 换页时**内容坐标重置**了，A 端地图却没重置 → 两套坐标系混排 | 帧头带 **epoch**（内容空间代号）：B 换页递增，A 端据此清地图 |
| 同一页内滚一会儿，地图的行号突然对不上 | 锚失败时把原点重置了 | 锚失败**只清索引、保留原点**；换页只由 epoch 标记 |
| 长截图里视口部分有黑带 | 地图里那一段没记住 | 长截图的**视口部分以实时画面为准**；范围 = 地图 ∪ 视口 |
| 长截图的"最后 H 行"不是当前屏幕 | 内容空间比视口长（滚下去又滚回来，下面还留着旧位置的内容） | 视口在长截图里的行号 = `origin - lo`（元数据 JSON 里有 lo/hi/origin）→ **别默认视口在底部** |
| 滚久了长截图底部变旧内容 | 视口那几行的写入被跳过（旧代码拿视口高度当行号上界） | 视口行号要用**内容空间的总行数**当上界；现在 e2e 每轮都比对"长截图的视口部分 == 实时画面" |
| 比对长截图偶尔失败（画面一直在动时） | 比对前 `await` 了一下存 PNG，中间来了新帧 → 实时画面已经变了 | 比对必须在**同一个 JS tick** 里做完：先抓帧缓冲，再 await 存文件 |
| 长截图越来越吃内存 | 字面量行无限增长 | 上限 **32MB**；超了先丢离原点最远的行，并压缩像素缓冲重排偏移 |
| 手机上 WASM 内存涨到 200MB+ | 池(96MB 硬上限) + 地图(32MB) + 历史环(4×11MB) | 已把上限压到 96/32MB；真机压测稳定在 ~140MB |
| 滚动越滚内容行号越怪 | 甩动跳过了内容 → 坐标上是洞 | 洞是诚实的（黑）；B 端 `canvas.lost` 会重新找原点 |

## 真机验收（razr 40）

| 症状 | 根因 | 处理 |
|---|---|---|
| 延迟 p90 偶发 15–18 秒 | 设备当时被别的任务占用（采语料） | 跑之前确认设备空闲；多轮取分位数 |
| 画面变慢但 CPU 不忙 | 帧率上限 30 → 最坏等 33ms 才有下一帧 | 默认上限提到 60（实测省约 4ms） |
| ImageReader 回调慢 | 缓冲少，等空缓冲 | 缓冲 3 → 4 张 |
| B 端重启后 A 端连不上 | 令牌每次运行都重新生成 → 握手被拒（`Reject{Token}`），自动重连会一直失败 | 令牌持久化在 `$HJDIR/token`；A 端退避重连并自动重开会话 |
| WebTransport 连不上 | 页面优先试 QUIC：需要 `navigator.webTransport`（安全上下文 ✓）+ 自签证书指纹（`GET /cert`）；失败会自动退回 WS | headless Chrome 默认关 QUIC（要 `--enable-quic`）；指纹要 base64 |
| 两个 A 端互相踢、延迟飙到 1 秒 | host 只允许**一个**连接，新连接顶掉旧连接；旧客户端自动重连 → 互相踢 | 顶掉之前先发 `Event::Session{Ended}`，A 端收到就**不再自动重连**；并注意调试时别留多个标签页 |
