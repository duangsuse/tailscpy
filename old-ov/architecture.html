活镜 · 架构与数据面

B（Android 手机）的虚拟屏 → 逐像素无损传到 A（浏览器/手机）；A 的点按 / 滑动 / 返回 → 注入回 B。

这一页回答三个问题：① 数据怎么流（B 抓帧 → 编码 → 通道 → A 解码 → 上屏）；② 每个部件负责什么；③ 为什么不用 H.264 视频流。

0px = 帧缓冲逐像素相等 布局层 / 精灵池 / 视频区（三层） Rust 端到端 自签证书 + Tailscale

1 · 一帧是怎么传的

2 · 像 tile 地图一样理解数据面

摄像机移动 = 整行搬移

列表滚 40px，本质是"地图往下挪 40 格"，不用重画。行哈希投票找出位移，不物化平移后的画面（省掉几十 MB 读写）。

tile 缓存 = 精灵池

滚出屏幕的行登记成条带（id = 内容哈希，相同内容自动去重），滚回来直接贴。返回上一页时整屏贴回，几乎免费。

回到旧地图 = 整帧引用

画面和之前完全一样就说"回到第 N 张地图"，1 字节。

新地块 = 字面量

只有真正新出现的内容才传像素：纯色块十几字节；照片类最贵（照片墙一屏 3.3MB → 可逆变换 2.3MB → 无损 WebP 1.6MB）。

每一步都可验证：编码器只发"已验证等于目标画面"的动作，所以任何组合都不会产出错误像素。

3b · tile 地图：把画面当无限画布

屏幕行 ↔ 内容行

每一帧带一个内容原点：屏幕第 0 行 = 内容第几行（可负）。滚动 = 原点变，tile 不动。

tile = 内容哈希

同一段内容在两端算出同一个 id → 自动去重。滚回来的内容直接命中，不用重发像素。

长截图 = 地图导出

A 端把内容空间里的 tile 拼成一张图（PNG）+ 一份 JSON（每段是条带还是字面量）——就是 tile 地图的内部状态。

验收：滚完 60 行后，A 端导出的长截图逐像素等于原始页面（cargo test -p hj-codec --test tile）。

4 · 延迟分段

环节典型值说明
输入注入 + 应用渲染 + 抓屏读回~45ms两个 vsync + 抓屏；未在 B 原生实现上量过
B：整帧比较 + 哈希2.2ms11.4MB RGBA（1080×2640×4），B 手机实测
B：编码（zstd-3）0.5–24ms随字面量大小；WebP 无损 4–581ms
网络字节×8/带宽 + RTT/2Tailscale 走 DERP 时会明显变差
A：解码PC 3ms / 手机 17–84ms与字面量字节线性相关
A：贴脏矩形≈0只贴变化矩形，不全屏
字节数就是延迟：A 端解码时间随字面量字节线性增长，传输时间同理。省字节的杠杆同时是省延迟的杠杆。

层东西要点
线格式长度前缀 + postcard快但不自描述 ⇒ 枚举只追加、字段不改序、不兼容升版本

6 · 相关开源项目

Xpra

最值得读：按窗口/区域自动选编码（无损/webp/jpeg/视频），滚动检测，文字与图片分解，图片有损后补到无损。

VNC Tight / CopyRect

矩形分类（纯色/调色板/JPEG）；CopyRect 是滚动最便宜的表达——我们的整行搬移就是它的加强版。

MRC (T.44) / DjVu

前景/背景/掩码三层混成："布局与图片独立质量"的理论原型，对应我们的布局层/精灵层。

JPEG XL patches

在图像格式内部做重复字形/图标去重——"字形精灵"是同一思路，只是我们还没实现。

scrcpy

交互与传输的工程参照：虚拟显示、输入注入、背压、按通道分流。

7 · 四个容易被误解的点

  • "有损精灵 + 升级"还没做：池里存的是原样的行，只有"见过再回来"才省；照片类内容的大头还在字面量里。
  • 无损 WebP 小一半但实时不可用：B 端编码一屏照片 0.5–1.1 秒（zstd 只要 30ms）→ 省照片字节只能靠"有损快档 → 升级"。
  • 视频层没有：协议留了通道，没有任何实现。
  • A11y 不在数据面上：协议 v2 已删；运行时从来没用过它，像素判定已能保证 0px。
  • 协议 v3 砍掉了整个合成层调试：只剩只读层列表；长截图改成从 A 端 tile 地图导出。
  • 换页时内容坐标会重置：所以帧头带 epoch（内容空间代号），A 端据此清地图——否则两套坐标系混排，长截图错位。
  • ≤30KB/帧对整屏照片不成立：照片级内容（壁纸、插画）无损就是 2.3MB；能做的是"先有损、静止后升级"（省首帧时间，不省总字节）。

8 · 几处必须记住的坑

  • pgrep -f 的模式若出现在自己命令行里会匹配到自己 → 后台任务永不退出。
  • Android 任意线程未捕获异常会 kill -9 整个进程 → daemon 自装 UncaughtExceptionHandler。
  • Kotlin 命令泵不能睡：一睡，后面的触摸/按键全排队。
  • 整帧哈希 = 行哈希的折叠，不是 hash64(整帧) → 两端定义必须一致。
  • Android 12+ 拉伸式越界回弹不是刚性平移 → COPY 不命中，退化成整屏字面量。
  • 控制端口只绑 Tailscale 网卡，不得 0.0.0.0；自签证书 ≤14 天要轮换。
